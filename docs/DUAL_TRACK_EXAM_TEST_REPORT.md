## 三、口径核对（实现与提示词契约逐条对照）

- 内容完成率仅由 `computeGoalProgress`（Σ Checkin.amount）计算；自评/知识点/考试排程均无法改变它。✅
- 掌握覆盖率分母=未归档知识点权重；rating≥3 为已掌握；无知识点显示「暂无掌握数据」而不渲染 0%。✅（单测+走查 1）
- 评估为追加式（source 固定 'self'），最新按 assessedAt+id；删除回算。✅（单测）
- 倒计时本地自然日：考试日 0、未来 N、已过「已结束 N 天」。✅（单测跨年/闰日）
- ExamPlanSlot.plannedMinutes（时间层）与 DailyPlan.plannedAmount（目标量层）并列展示、UI 明示不相加。✅（总览文案）
- 实际投入分钟沿用 FocusSession/Checkin.minutes 去重管线；未记录显示「未记录时长」。✅
- 全局预算未配置时明示，不猜某考试上限为全局。✅（预览 UI + 单测）
- 清单勾选只写 doneAt，不改评分/打卡/专注。✅（实现隔离 + 用例注释）
- 保存失败保留表单内容并提示「未保存，可重试」。✅（各表单 catch 路径）

## 五、剩余风险与限制

1. 三端数据各自独立，无自动同步（产品边界，非缺陷）。
2. 掌握覆盖率为真实自评投影，不代表客观成绩；UI 已按「自评掌握情况」表述。
3. SQLite v3 迁移语句已随仓库交付，但原生端未在本机执行过（无工具链）；IndexedDB 升级已由 fake-indexeddb 自动化验证。
4. 备考阶段「生成草案」的模板比例（40/35/15/10）是可编辑的建议值，不是规范。
5. 周报中「本周评估次数」口径已实现于双轨统计（`getMasteryStats.counts`），周报页仅展示既有统计，未额外追加评估行（避免改动既有周报口径；如需可在阶段 4 迭代）。
